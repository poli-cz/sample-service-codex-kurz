# LAB-201: Westgard rules for control samples

**Type:** feature · **Component:** labcore · **Reporter:** quality management

## Problem

Every analyzer run includes control samples with a known target mean and standard deviation
(SD) per control lot. Today the operators judge the control values by eye. The lab follows
the Westgard multirule scheme and wants the service to evaluate it.

## Request

Add `lab::qc::evaluate_westgard` to `labcore` (new header `labcore/qc_rules.hpp`).

```cpp
namespace lab::qc {
struct Violation {
  std::string rule;   // "1-2s", "1-3s", "2-2s", "R-4s", "4-1s" or "10-x"
  std::size_t index;  // index of the value that completed the rule
  friend bool operator==(const Violation&, const Violation&) = default;
};
[[nodiscard]] std::vector<Violation> evaluate_westgard(std::span<const double> values,
                                                       double target_mean, double target_sd);
}  // namespace lab::qc
```

Input: control values in measurement order, target mean (M) and target SD (S) of the lot.

| rule | fires when |
|---|---|
| `1-2s` | one value beyond M ± 2S (warning) |
| `1-3s` | one value beyond M ± 3S |
| `2-2s` | two consecutive values beyond the same 2S limit (both above M + 2S or both below M − 2S) |
| `R-4s` | two consecutive values, one above M + 2S and the other below M − 2S |
| `4-1s` | four consecutive values beyond the same 1S limit |
| `10-x` | ten consecutive values on the same side of the mean |

- "Beyond" means strictly greater than the upper limit or strictly less than the lower limit.
  A value exactly on a limit does not exceed it. A value exactly on the mean is on neither
  side and breaks a `10-x` run.
- A rule is reported at every index where the window of values ending at that index satisfies
  it. One value can trigger several rules; `1-2s` is always reported, also next to other rules.
- Output order: by index, and within one index in the order of the table above.
- `target_sd <= 0` throws `std::invalid_argument`. Empty input gives an empty result.

## Acceptance criteria

- GoogleTest tests written before the implementation, in `tests/labcore/qc_rules_test.cpp`.
- Tests cover every rule, values exactly on the 1S, 2S and 3S limits, runs longer than the
  rule window, both sides of the mean, and invalid SD.
- `python scripts/check_all.py debug` passes, `python scripts/check_all.py tidy` reports nothing.
- No new dependencies, no `NOLINT`, no `-Wno-*`.

## Out of scope

Wiring the rules into the service (commands, `C|...` records from the analyzer); that is a
follow-up ticket.
