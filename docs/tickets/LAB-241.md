# LAB-241: Service command PRIORITY

**Type:** feature · **Component:** labcore, apps/sample-service · **Reporter:** lab operations

## Problem

A routine sample sometimes turns out to be urgent after it was submitted. Today the operator
has to `CANCEL` it and `SUBMIT` it again, and it loses its place.

## Request

New command `PRIORITY <sample-id> <STAT|URGENT|ROUTINE>` that changes the priority of a sample
waiting in the queue. It prints exactly one JSON line:

| situation | output |
|---|---|
| sample waiting in the queue | `{"event":"priority","sample_id":"S-100005","priority":"URGENT","changed":true}` |
| sample not waiting (on the rack, measured, unknown) | `{"event":"priority","sample_id":"S-100005","priority":"URGENT","changed":false}` |
| wrong number of arguments | `{"event":"error","message":"usage: PRIORITY <sample-id> <STAT|URGENT|ROUTINE>"}` |
| unknown priority | `{"event":"error","message":"unknown priority ASAP"}` |

- In its new priority the sample keeps its original submission order: it goes in front of
  every sample of that priority that was submitted after it.
- Raising a sample to STAT does not preempt anything on the rack (preemption happens only
  on `SUBMIT`).

## Acceptance criteria

- The queue logic lives in `labcore` (`SampleQueue`), the command only parses and prints.
- GoogleTest tests for the queue and for the command, including both errors.
- README command table updated.
- `python scripts/check_all.py debug asan tidy` passes.
